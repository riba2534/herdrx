## 设计实施说明

尺寸控制采用独立的访问连接，观察流与原 InputQueue 持续保留。这减少了切换几何控制造成的输入收尾与换流风险；需要关闭观察流时仍使用已有 Finish，认证撤销立即取消。控制进程的首个有效 full frame 是 attach 成功的证据，子进程启动不代表控制成功。

控制目录以 owner、主机接入记录、runtime 代次和稳定 terminal ID 为键。只认本站登记的旧连接；其他接入别名由 Herdr 的 direct-control 互斥最终裁决。每终端单独串行远程操作，全局目录锁不跨网络调用。

## 真实整链回归发现并修复的画布问题

真实双浏览器测试发现，Herdr CLI observe 的画布尺寸固定为启动参数：控制连接已把 PTY 改成 104×39，观察帧仍为 120×40。仅检查 PTY 或模拟 WebSocket 无法发现此问题；不能用这类帧头宣称实际尺寸已收敛。

实现新增窄范围的原生 ObserveTerminal 适配器，沿用已审阅的协议 20/22 和现有帧解码。它只支持观察画布 resize，拒绝文本输入、滚轮、控制 attach 等写命令；真实任务输入仍走原有独立队列。初始画布读取实际 PTY，本站控制帧变化同步所有观察画布，没有本站控制时按快照周期只读校准外部尺寸。无法读取精确几何时保留原 CLI 观察，但禁用需要动态画布的任务尺寸控制并给出提示。

这项变更由实际失败推动，替代设计最初的纯 CLI observe 路径；没有迁移 ClientShell，也没有把观察画布 resize 等同于任务 resize。独立的真实三版测试分别覆盖无控制者、带像素的外部直接控制、带像素的原生 TUI，要求观察画布变化时 PTY 四维、PID、SIGWINCH 保持不变。
