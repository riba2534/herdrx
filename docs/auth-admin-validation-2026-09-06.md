# 远程任务独立运行与访问管理验收

> 本文记录前一轮验收。注册默认值、后台开关、本机角色限制和 schema 2 的当前结果见[角色、注册与用户管理复核](access-policy-validation-2026-09-06.md)。

日期：2026-09-06。范围：[最终实施方案](design/auth-admin-remediation.md)中的连接生命周期、5 个认证问题、管理员功能、迁移及网站部署配置。本次完成代码实现与本地候选验收；没有切换已有体验实例，也没有提交或推送源码。

## 已实现

- Web 登录统一准入和撤销：注销、到期、账号禁用、管理员注销登录均关闭对应访问；旧 WebSocket 返回 4401。数据库故障停止访问并允许重试。连接注册和撤销共享短临界区，不在锁内等待远程网络。
- 无效邀请先拒绝，再进行密码哈希；最终注册事务再次验证。全局密码哈希默认最多 2 个，注册最多 1 个，并发请求取消不会提前释放正在计算的额度。
- 可信代理按单个 IP/CIDR 显式配置，安全解析转发链；登录按客户端 IP 和 IP/邮箱组合限流。所有写接口和 WebSocket 校验完整来源，认证写接口只接受 JSON。
- 受保护 API 的 401 清除浏览器认证；403、服务故障及网络中断不误退出。旧请求或旧连接不能清除新登录。跨标签页只发送重新验证提示，不广播 token；重连不重放输入。
- 管理员页面提供用户启用/禁用、登录列表及单条/全部注销、邀请创建/列表/撤销、审计查询。禁止自禁用和关闭最后一位管理员；关键修改与审计同事务提交。
- 禁用账号同时删除登录和通知订阅，取消该用户的后台访问。启用不会恢复旧登录或旧订阅。
- 共享 SSH/Tailcat 传输按引用使用和空闲回收。关闭观察连接只释放客户端和通道，远程 Herdr 与 PTY 的生命周期由远程主机负责。

## 独立虚拟机故障验收

工作台和远程 Herdr 分别位于两台隔离 KVM 虚拟机，拥有各自的内核、磁盘和进程。远程 Herdr 0.8.2 在命名测试会话中独立启动，Shell 任务持续输出并将递增计数写入远程文件。SSH 与 Tailcat 都使用真实接入；Tailcat 经正常网页配对接口完成绑定。

验收从远程主机的 `/proc`、Herdr 拓扑和计数文件取证，不以工作台缓存判断存活。主测试 Herdr PID 为 106，任务 PID 为 153，pane 为 `w1:p1`，下列操作前后均未替换。

| 故障/操作 | 结果 |
|---|---|
| 关闭观察连接、浏览器突然断开 | SSH/Tailcat 均保持远程任务推进 |
| 注销一条登录、保留另一条登录 | 原任务继续，另一条有效登录仍可访问 |
| 正常停止网站进程并重启 | 原 PID 和 pane 保留，可以重新连接 |
| 两条链路打开时直接关闭工作台虚拟机，未执行 guest 优雅关机 | 远程计数 29480 → 29627；工作台保持离线时继续到 29793 |
| 从原磁盘重新启动工作台虚拟机 | Tailcat 和 SSH 均连回原 pane，计数继续到 30105；无需重建远程任务或重新配对 |
| 本机辅助接入模式的观察关闭、注销、网站进程停止 | 远程测试机内单独运行的本机模式验证通过；不用于替代上面的独立主机证明 |
| 管理员通过真实浏览器禁用观察终端的成员 | xterm 清除且要求重新登录，远程计数 45188 → 45254，PID 不变 |
| 两个独立 Chromium 进程同时观察原 pane，注销其中一条登录 | 被注销页面退出，另一浏览器保持连接并收到新输出；远程计数 107144 → 107156，PID 不变 |

另建随机高频输出任务，分别让 SSH/Tailcat 观察流累计约 2 MiB 的数据不发送 ACK。约 26 秒后观察流因额度耗尽关闭；对应任务计数分别从 43 → 2331、2575 → 4864，任务 PID 保持不变。说明观察输出背压及观察客户端回收没有暂停远程任务。

显式关闭资源也单独验证：浏览器显示“其中运行的进程也会结束”的确认，确认关闭测试 workspace 后仅目标任务结束，原主测试任务继续运行。访问注销和关闭 Herdr 资源的语义保持区分。

虚拟机测试证明了两台主机的生命周期隔离；它不等于两台物理机的断电测试，也不替代 Wi-Fi/蜂窝网络、不同运营商或 72 小时运行验收。

## 掉电中发现的持久化问题与修复

首次整机掉电验收中，原 `synchronous=NORMAL` 配置丢失近期创建的 Web 登录及 Tailcat 主机记录。远程任务存活，但工作台无法使用丢失的访问记录恢复连接。

现改为 WAL + `synchronous=FULL`，在事务成功返回前同步落盘。重复同一整机掉电操作后，新登录及配对记录保留；掉电前已撤销的登录和邀请也保持撤销。同步级别的持久性差异见 [SQLite 官方文档](https://www.sqlite.org/pragma.html#pragma_synchronous)。

## 迁移与交付

- 历史 schema 0 的隔离 fixture 升级到 schema 1，账号、密码哈希、登录、加密凭据和主机标识不变；再次启动成功，邀请撤销保留，较高 schema 拒绝打开。
- 对已有数据库只读备份执行离线迁移：比较 9 张表所有原有字段，值均不变；重复迁移和完整性检查通过。没有启动 API 或访问原有主机。
- Linux amd64/arm64 候选网站镜像均构建成功。amd64 候选通过 nonroot、显式 bind mount、健康/资源、初始化和容器重建后登录检查。
- Caddy HTTPS 配置使用独立网络及单个可信代理 IP，关闭后端公开端口，强制 Secure Cookie。所有持久化仍使用目录 bind mount。
- 发布流程继续为 GitHub Actions → ZOT → 工作台主机主动拉取。CI 增加浏览器及 Caddy 验收，两种架构镜像分别在原生 runner 测试后发布。

源码尚未提交/推送，首次 GitHub Actions 发布和 arm64 原生运行仍待该流水线执行。本机完成的是 arm64 构建，不能标为原生运行通过。其他正式发布差距继续记录在[发版清单](release-readiness-2026-09-06.md)中。
