# 移动端缩放与尺寸控制

日期：2026-09-25。本文记录这一轮移动端缩放的调研结论、实现取舍和验证范围。先前的尺寸控制设计见 [终端尺寸与 Herdr 兼容](design/terminal-sizing-and-herdr-compatibility.md)，更早的显示验收见 [字号、缩放与跨端显示验收](display-validation-2026-09-06.md)。

## 调研结论

- **远端画面不需要改尺寸就能完整拿到。** Herdr 的观察连接不会改变 PTY；服务端按观察者声明的行列输出画面，多出的部分裁掉、不足的部分补空白，不做缩放。网页按 PTY 的实际行列观察，就能拿到完整的桌面网格，缩放和平移都在前端完成。
- **把远端改成手机尺寸有持久代价。** Agent 会按窄宽度重新输出，已经写进历史的硬换行不会恢复，桌面端的历史也随之受损（herdr #2404、#2665）。Claude Code 在软键盘每次开合时都会重绘；有人在 Herdr 里复现过：PTY 从 49 列恢复到 103 列后，它仍然按 49 列输出。
- **手机竖屏无法可读地显示桌面宽度的 pane。** 按 Chromium 设备模拟实测，远端为 173×54 时，iPhone 15 竖屏以 14 px 只能看到 45×38（约 18%），完整显示需要缩到 3.7 px；横屏 760 px 宽可以以约 10.5 px 铺满 120 列。
- **业界做法**：原生终端 App 用捏合调整字号并同步 PTY（Blink、Termius、Termux）；Zellij 0.45 的网页端以 visualViewport 驱动布局，并提供“按桌面行列渲染 + 平移”的开关；官方 Agent 手机客户端（Claude、Codex、Happy、Paseo）都没有在手机上镜像终端，而是改成对话界面。多客户端尺寸冲突的主流做法是“由显式认领的客户端控制尺寸”，闲置设备不参与。

## 实现

### 本地显示：只影响当前页面

- “自动”改为三档：先以字号上限完整显示远端画面；放不下时铺满宽度、上下滑动；铺满宽度也需要小于下限（电脑 10 px，手机 9 px）时，保持可读字号并四向滑动。
- 手机默认改为“自动 13 px”。旧版本写入的手机默认值（固定 14 px、100%）只在首次读取时迁移一次；其他手机设置都视为用户的选择，原样保留。
- 显示偏好分为电脑布局、手机布局和手机横屏三份；只有触屏设备区分横竖屏，桌面窄窗口始终使用手机布局这一份。升级后横屏先沿用当时的手机设置，之后两者分别保存。
- 触屏上在终端画面内双指捏合即调整本地字号：手势过程中只用 CSS transform 预览，松手后提交一次，字号限定在 10–28 px；捏到 9 px 以下切换为“完整显示”。终端区域不再放大整页，页面其他区域仍可使用浏览器缩放。
- 画面右上角的角标显示远端行列和控制状态。手机上常驻；电脑上只在画面被裁切、由其他窗口控制或其他窗口释放后留下较小尺寸时出现。点开后可以切换显示方式、按 1 px 调整字号、切到对话视图，以及操作任务尺寸。

### 共享尺寸：只有显式操作才改变远端

- 接管前，角标菜单写明远端会从多大改成多大；列数少于 50 时提示 Agent 的表格和 diff 可能折行。
- 控制期间，触屏上有输入框获得焦点、且可视视口比获得焦点前变矮时，视为键盘或候选栏遮挡：行数和字号保持不变，画面滚动到光标处。失焦后保留 1 秒收起宽限，避免键盘动画未结束时先缩再放。旋转屏幕、调整字号或分屏变化仍会重新排版。resize 的合并窗口从 80 ms 调整为 250 ms。
- 手机的左右安全区改用终端视口的外边距（原先是内边距，而滚动容器会把横向溢出的文字画进内边距，也就是刘海区域）。计算控制尺寸时只算可见宽度：iPhone 15 横屏接管时，原先申请 99 列、只能看到 85 列，现在申请 92×18，与可见区域一致。
- 释放控制分成两种：“恢复为 173×54 并释放”先把远端改回接管前的尺寸，等 Herdr 的画面确认后再释放，最多等待 2 秒；“释放控制”则保持当前尺寸。进入后台、切离终端、断线等被动释放依然不会自动恢复。
- 本站其他窗口正在控制时，角标显示“其他窗口控制 45×38”，并提供“转到此窗口控制”。本窗口看到其他窗口控制并释放后，如果远端网格不到本窗口可容纳宽度的 60%，角标提示“较小”，可以“按此窗口尺寸恢复”：取得控制、等待画面确认、再释放，只调整一次。原生 Herdr 窗口本来就比浏览器小的情况不提示。恢复与一次性调整都带控制代次校验，期间用户重新取得的控制不会被延迟回调释放。

### 布局

- 手机单 pane 布局取消 pane 头部。Terminal / Chat 开关移到顶栏，控制状态显示在角标上，终端多出一行 44 px 的高度。
- 软键盘弹出时，底部输入区不再保留 Home 指示条的安全区留白。
- 平板等触屏设备在电脑布局下：
  - 标签栏新增辅助键按钮；
  - 顶栏、侧栏和主区域按 `env(safe-area-inset-*)` 留出状态栏和 Home 指示条；
  - 返回主机和 Terminal / Chat 开关的触控目标调整为 44 px；工作台主题里更紧凑的侧栏行高（32 px）只用于鼠标，触屏上工作区行与侧栏底栏保持 44 px，底栏按钮不再伸进 Home 指示条区域。

## 验证

### 单元测试

前端类型检查、lint 通过。Vitest 共 54 个文件、591 项测试全部通过。新增的覆盖如下：

- 分档适配；
- 手机默认值迁移、横竖屏分别保存；
- 遮挡高度只在触屏且正在编辑时计算，失焦后的收起动画期间继续计算；
- 键盘分步弹出与完全弹出都不触发 resize，窗格本身变化仍会触发；
- 扣除安全区后的列数；
- 恢复原尺寸时，等画面确认后才释放；延迟回调不会释放用户重新取得的控制；
- 一键按此窗口尺寸恢复，只在其他窗口释放后提示；
- 角标消失时菜单一并关闭；
- “其他窗口控制”角标；
- 捏合只提交一次，捏到最小以下切换为完整显示；
- Safari 手势事件的拦截；
- 手机顶栏的视图开关；
- 平板辅助键。

### 浏览器回归

浏览器回归脚本同步更新了以下内容：

- 释放按钮的文案；
- 手机不再有 pane 头部；
- 手机默认字号；
- 角标选择器；
- 手机空间占比的计算：不再从分母里扣除 pane 头部。

`test-workbench-display.mjs` 新增两项。一是在输入框有焦点时模拟键盘，确认控制尺寸和行数都不变。二是在 Chromium 中用 CDP 发送真实的双指触摸：确认手势过程中有预览、松手前不发 resize、松手后字号从 13 px 变为 26 px 并只发一次 resize、页面缩放比例保持 1，并且只写入一份显示偏好。

### 完整浏览器回归

在本机按 CI 的浏览器矩阵执行了全部 19 项浏览器回归，均通过：

- 认证、Tailcat 接入、密钥与文件夹、外观、自绘控件；
- 终端渲染与主题、工作台显示、输入框、对话与媒体；
- 桌面显示、工作台空间、闪烁、手机滚动；
- PWA 与网络恢复；
- 使用 SHA256 校验过的 Herdr 0.9.1 做真实 PTY 尺寸控制，在 Chromium、Firefox、WebKit 下各跑一遍。

代码审查修复、安全区与侧栏调整之后，又分两次从头完整执行，结果都相同。

一项预期中的变化：由于 resize 合并窗口加长，真实 Herdr 测试里“视口变化到观察到目标网格”的本机回环延迟，p50 从约 110 ms 变为约 280 ms（Chromium 278.9 ms、Firefox 283 ms、WebKit 273 ms）。这是用一次性的延迟，换取连续变化时不反复触发 SIGWINCH。

### 改动前后实测

测量条件如下，改动前后完全相同：

- 浏览器：Chromium，按设备模拟视口、像素比、触屏和安全区；
- Herdr：SHA256 校验过的官方 Herdr 0.9.1，使用隔离会话；
- 远端网格：173×54；
- 被测页面：默认显示偏好，只观察，不接管。

表中各列的含义：

- **默认可见**：本地能直接看到的远端网格范围，以及它占整个远端网格的比例。
- **接管后远端**：选择“使用此窗口尺寸”后，远端 PTY 被改成的尺寸。
- **安全区越界**：进入刘海、状态栏或 Home 指示条区域的控件或终端文字的数量。

| 设备 | 改动前：默认可见 / 接管后远端 / 安全区越界 | 改动后：默认可见 / 接管后远端 / 安全区越界 |
|---|---|---|
| iPhone SE 竖屏 | 14 px 43×31（14%） / 43×31 / 0 | 13 px 46×36（18%） / 46×36 / 0 |
| iPhone 15 竖屏 | 14 px 45×38（18%） / 45×38 / 0 | 13 px 48×43（22%） / 48×43 / 0 |
| iPhone 15 横屏 | 14 px 85×15（14%） / 99×14，比可见多 14 列 / 2 | 13 px 92×19（19%） / 92×18 / 0 |
| iPhone Pro Max 竖屏 | 14 px 49×43（23%） / 49×43 / 0 | 13 px 53×49（28%） / 53×49 / 0 |
| Pixel 7 竖屏 | 14 px 47×48（24%） / 47×47 / 0 | 13 px 51×53（29%） / 51×53 / 0 |
| Galaxy Z Fold 折叠态竖屏 | 14 px 39×45（19%） / 39×45 / 0 | 13 px 42×51（23%） / 42×51 / 0 |
| iPad mini 竖屏 | 14 px 87×54（50%） / 86×58 / 0 | 13 px 93×54（54%） / 93×65 / 0 |
| iPad Pro 11 横屏（PWA 安全区） | 14 px 114×43（52%） / 114×43 / 11 | 14 px 114×40（49%） / 114×40 / 0 |

几点说明：

- 手机竖屏多出的行数来自两处：取消了 pane 头部，以及字号从 14 px 调到 13 px。
- iPad Pro 横屏少了 3 行，是因为顶部状态栏和底部 Home 指示条的安全区现在会让出来，原先有 11 处控件被它们遮住。
- 平板电脑布局下最小的触控目标从 26 px 提升到 43 px。仍不足 44 px 的只有主机标签和标签页，它们高 43 px，是 44 px 的行扣掉 1 px 边框。
- 手机横屏的矮视口布局仍使用 32 px 触点，这是为保住终端行数的既有取舍。

## 未验证

- 所有浏览器结果都来自 Linux 上的 Chromium、Firefox、WebKit 设备模拟。没有在真实 iPhone、Android 或已安装的 PWA 上操作。
- 软键盘、安全区和系统字体缩放都是模拟的。以下几项需要真机确认：
  - 真实键盘的动画步进；
  - 中文输入法候选栏；
  - iOS standalone PWA 中的 visualViewport 事件；
  - iOS 上 `gesturestart` 的拦截效果；
  - 键盘弹出时 `safe-area-inset-bottom` 的取值。
- 9 px 与 10 px 这两个可读下限，以及 50 列的提示阈值，来自调研中的经验值，还没有做真实用户的主观可读性确认。
- 两个待复测的边界：
  - 恢复原尺寸后，Claude Code 是否仍卡在旧宽度（上游已有复现）；
  - 不在原生客户端前台的 pane 被观察时是否持续推帧。
