# 发送防护与对话框卡片

本地输入框和 Chat 输入框点「发送」时，工作台会先读取一次目标终端当前可见的画面，确认可以安全输入后，再把正文和一次回车送进终端。远端 Herdr 与 Agent 照常运行，这个检查只决定这一次发送要不要打字。

## 发送前检查

| 画面状态 | 结果 |
|---|---|
| 底部弹着选择对话框（权限确认、计划确认、提问、信任目录等） | 不发送，内容保留在输入框，并显示对话框卡片。文字发进去会被当成选项 |
| 多选题（选项带勾选框） | 不发送，也不显示卡片，提示在终端里操作 |
| 底部像是对话框但认不出（有“Esc to cancel”等按键提示，或带光标的编号选项） | 不发送，提示“终端底部像是有一个对话框，请在终端里回答后再发送” |
| 提问框的光标停在“Type something.”或“Other”自由输入项上 | 照常发送，文字进入对话框自己的输入框 |
| Claude 输入框里有电脑上打了但没发的字 | 不发送，询问“电脑上有未发送的输入，仍要发送吗”。确认后这次发送跳过草稿检查，两段内容会拼在一起提交 |
| 输入框里只有灰色的预测建议 | 视为空，照常发送 |
| 读不到画面 | 不发送，提示检查主机连接后重试 |
| 其他（Shell、未认出的程序） | 照常发送 |

每次发送带一个消息编号，正文不变时沿用同一个编号（结果未知时刷新页面后也沿用；同一登录的另一个标签页发相同正文算另一条消息），服务端在 10 分钟内只处理一次：网络断在半路后再点发送，如果上一次已经送达，只确认不重打；如果上一次已开始输入但结果不确定，会提示“上一次发送结果不确定，请先查看终端再决定是否重发”，不会自动重发。看过终端后再点一次发送，才作为新消息发出。反向代理返回的网关错误同样按“结果未知”处理。

询问“仍要发送吗”只针对发起发送的那个终端：结果回来前已切到别的终端时不会弹出，确认框打开后切走则视为取消。确认期间又加了还在上传的图片时不会强行发送，请等上传完成后再点发送。

开始往终端里输入后，浏览器关闭或断网不会把正文和回车截在半路；退出登录、登录过期或账号被禁用时，尚未送出的部分立即停止。每次成功发送都记入审计日志，只记终端、字数和是否确认过草稿，不记正文。

## 对话框卡片

当前终端的 Agent 状态为“需要你”时，工作台在终端右上角（手机上在顶部）显示对话框卡片：标题、说明和选项按钮。页面可见时每 2 秒刷新一次；Agent 不再等待时卡片自动消失，也可以点关闭按钮收起，出现新的对话框时会再显示。

点选项后，服务端先重新读屏，确认对话框没有变化，再按键：带编号的选项按对应数字（超过 9 个选项时改用方向键），不带编号的列表从当前光标位置按上下方向键后回车。回答后卡片隐藏约 3 秒等终端重绘；同一个命令再次请求确认时卡片会重新出现。对话框已经变化或已经关闭（例如已在电脑上回答）时，什么都不按，卡片刷新并提示重新选择。按键结果不确定时不重试，请先查看终端。每次回答都会记入审计日志。

## 边界

- 只识别画面底部的选择框：选项紧贴在“Enter to confirm / Esc to cancel”等按键提示上方（按键提示下方只允许 Agent 自己的状态行，退出 Agent 后残留在 Shell 提示符上方的旧对话框不算），或者带光标的编号选项本身在底部、上方有对话框边线。输入框里的内容、历史记录、Shell 输出都不算。认不出的对话框不显示卡片；底部看起来像对话框时仍会拦下发送，请切到终端直接操作。
- 不编号的选项折成多行时无法区分续行与下一个选项，不显示卡片。
- 卡片选中“Type something”之类的自由输入项后，在输入框里发送文字即可填入。
- 草稿判断依据 Claude 输入框的颜色：灰色是建议，其他颜色的文字视为草稿。终端不输出颜色时，输入框里的任何文字都按草稿处理，需要确认后才发送。
- 工作台只读取画面和发送按键，不会关闭 pane 或结束 Agent。
