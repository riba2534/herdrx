# Tailcat 安装引导验收

本次将直接填写连接字符串的入口改为「安装 CLI → 后台运行 → 绑定主机」。安装步骤包含 GitHub Releases、固定版本命令、架构下载与校验说明；后台步骤包含 Herdr 前置条件、setup/status、linger 和排障；只有最后一步填写一次性绑定凭据。

## 已完成的本地验证

- Go modules 校验、vet、全部普通测试和 race 通过。CLI 测试包含真实子进程与 IPC、回环 DERP/SSH 配对，以及旧配置损坏或旧服务运行中时 setup 不生成替代身份。
- 70 项前端单元测试、类型检查、lint 和生产构建通过。
- Chromium、Firefox、WebKit 在 320、390、768、1440 像素宽度完成三步引导、前后切换、下载元数据状态、复制与 HTTP 剪贴板降级、主题、焦点和关闭验证。安装与下一步操作不会提交绑定。
- 绑定模拟接口验证：明确点击绑定后才提交，受理后清除凭据，刷新自动回到绑定步骤并续接，失败展示可执行提示，成功进入主机。浏览器仅保存续接任务标识，不保存绑定凭据。
- 新增 Release 元数据测试覆盖鉴权、草稿/附件缺失、正式版优先、预发布、非法标签、上游错误、缓存、并发请求与浏览器取消。出站请求固定到公开仓库且无用户凭据。
- 安装器 8 个场景覆盖固定版本、双架构选择、PATH 中的空格、校验失败、重复/缺失校验值、版本不匹配、下载失败、归档软链接、已有备份软链接、旧文件保留和重复安装。
- 发布器 5 个隔离模拟场景覆盖上传草稿、重新下载校验后公开、未提交源码拒绝、远端标签变化、已公开版本拒绝覆盖及损坏下载保留草稿。没有对真实 GitHub 执行发布操作。
- Linux 双架构候选压缩包、离线教程、安装脚本及 SHA256SUMS 已构建，检查全部附件和 ELF 架构；本机 x86_64 实际运行候选 CLI 的 version/help/offline status 通过。
- 现有认证、密钥/文件夹、主题、工作台显示、终端渲染、滚动闪烁和手机触摸滚动回归通过；部署配置检查、镜像发布脚本测试和 Actions 语法检查通过。

## 验收中修复的问题

重新检查版本会移除原重试按钮，可能让键盘焦点离开弹窗；现在将焦点留在步骤标题。下一步按钮与提交按钮曾复用 DOM 节点，返回上一步后再次继续可能触发表单提交；现在隔离按钮节点并取消下一步点击的默认动作，浏览器测试明确断言切换步骤不提交。

移动端保留可见标题和操作区，长教程在弹窗内容区滚动。旧 connect 输出不再将进程运行误报为「已配置登出保活」，并引导实际检查 linger。

## 尚未执行

当前公开仓库仅有初始 README，暂无 GitHub Release。候选包记录 `source_dirty: true`，发布器拒绝发布它；首次公开分发需提交源码、在干净版本上打包，再完成远端流水线与公开下载验收。

本次没有在 ARM64 实机运行候选 CLI，没有执行 systemd 用户登录/登出/reboot 的完整双架构验收，也没有扩大到真实跨运营商网络或长期运行测试。Release 流水线已配置 ARM64 原生执行门禁，但配置不等于执行证据。下载 SHA-256 校验不等于签名更新通道已经交付。
