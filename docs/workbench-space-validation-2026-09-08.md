# 工作台可视面积与导航重设计验收

## 问题与设计

手机原布局同时常驻主机栏、工作区栏、标签栏、终端标题栏，以及本地输入、模式说明、辅助键。390×844 浏览器视口的实际终端高度只有476.2px。桌面上下分屏之间也保留完整标题栏和源终端的分隔间隙。

本次调整：

- 手机顶部合并为44px导航，显示当前位置，点击打开位置选择，优先展示当前分屏和标签页，其后为工作区、Agent和主机。设置、终端工具和辅助键保留明确入口。
- 输入框默认单行44px，中文字号16px，多行内容自动增高至104px。输入方式放在可键盘操作的菜单中，空闲说明不再占一行；发送和异常回执仍显示。
- 辅助键默认折叠，展开入口和快捷键均保持当前输入焦点。切换面板可收起或恢复输入框。
- 终端标题和工具改为浮动展开，打开或收起都不改变终端尺寸。桌面分屏填满源终端分隔间隙，边界只保留1px。
- 桌面和手机的字号、输入方式继续独立保存；本地草稿仍按主机和分屏隔离。输入发送语义保持不变。
- 切换位置使用已有的焦点受控弹窗；创建工作区失败在弹窗内显示，避免错误被遮挡。

## 测量

同一构建、同一合成数据、相同视口，测量 `.terminal-viewport` 的实际几何尺寸。表格不包含系统安全区；安全区单独验证。

| 手机视口 | 调整前高度/占比 | 调整后高度/占比 |
|---|---:|---:|
| 440×956 | 588.2px / 61.5% | 859px / 89.9% |
| 390×844 | 476.2px / 56.4% | 747px / 88.5% |
| 320×720 | 352.2px / 48.9% | 623px / 86.5% |
| 844×390 横屏 | 127px / 32.6% | 293px / 75.1% |

桌面1440×900上下分屏，每屏终端从384px增至419px；2560×1440每屏为689px。测试也覆盖左右分屏和源布局中的1个字符宽/高分隔间隙，网页边界均不超过1.5px（允许小数像素取整）。

Chromium模拟440×956设备的顶部62px、底部34px安全区后，实际可用高度860px，终端763px，占88.7%。

## 自动验证

`make web-build` 后运行：

```sh
HERDRX_TEST_ENGINES=chromium,firefox,webkit node scripts/test-workbench-space.mjs
```

可选设置 `HERDRX_SPACE_ARTIFACTS=/absolute/output/path` 保存截图和原始几何数据。新脚本已接入CI。

脚本使用本地HTTP和WebSocket合成主机，不连接用户正在运行的远程任务，覆盖：

- 手机四组视口、软件键盘缩小可视高度、iPhone安全区、桌面两组视口及横竖分屏。
- 主机、工作区、标签页、分屏完整导航；布局和导航不会发送终端输入。
- 工具打开、关闭、Escape后焦点恢复；切换辅助键不让输入框失焦。
- 键盘显示/隐藏过程中草稿和本地/直接输入方式不变，xterm节点不重建。
- 已经处于直接输入模式时，再次选择该模式仍聚焦终端，明确键入的测试字符串按原值送达。
- 终端工具浮动显示而不改变几何尺寸；空闲输入框不被无内容行撑高。

布局、工作台显示及输入框回归在Chromium、Firefox、WebKit全部通过；桌面显示、界面外观、PWA三引擎通过；触摸滚动在Chromium/WebKit通过；终端无闪烁检查未出现空白或半帧。完整前端单测121项通过，类型检查、lint和构建通过。

## 快速尺寸切换回归

原有跨端显示测试在新版布局下暴露了真实渲染异常：连续收缩/恢复视口后，xterm报告46行但缓冲区只有45行，后续打印抛出异常，写入回调和ACK停止。修复前通过独立浏览器探针和单测复现。

自适应终端现在根据视口计算并发送期望尺寸，收到新的远端画面后才改变当前网格，避免本地提前缩放破坏仍在显示的内容。桌面的固定/适应窗口显示保持原语义。

`test-workbench-display.mjs` 保留原有四组旋转与键盘测试，并加入40次快速尺寸切换、等待稳定后验证末行和右边界、无浏览器异常、终端连接不重建。三引擎均通过；额外40次切换后连续四次同尺寸重绘也通过。

## 验证范围

以上为浏览器自动化及安全区/可视高度模拟；没有把实体iPhone键盘、真实安装PWA或用户远程任务的实际显示声称为已经手工验收。
