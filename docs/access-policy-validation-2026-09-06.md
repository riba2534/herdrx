# 角色、注册与用户管理复核

日期：2026-09-06。本次补充[此前的认证验收](auth-admin-validation-2026-09-06.md)，以当前角色和注册要求为准。

## 复核发现与处理

| 项目 | 复核前 | 当前行为 |
| --- | --- | --- |
| 注册默认值 | 环境变量默认 `invite`，后台没有注册开关 | 新实例和首次升级到 schema 2 均为关闭；管理员手动开启，设置保存在数据库 |
| 管理员初始化 | 已有令牌和空用户表限制 | 保留；并发及重启测试确认初始化只能创建一个管理员账号，正常重启不重新初始化 |
| 本机 Herdr | 添加接口和页面已有角色判断；历史记录、连接层及持续访问缺少完整复核 | 创建、列表、详情、修改、快照、WebSocket、图片上传、连接工厂和已有访问均检查角色与归属 |
| 用户管理 | 已支持禁用/启用、注销登录、邀请撤销和审计 | 保留并复测，增加邮箱/名称搜索、角色和启用状态筛选 |
| 注册中的设置变更 | 仅在请求入口读取模式 | 注册提交事务再次验证开关和版本；关闭及关闭后重开都能阻止旧请求提交 |

系统角色只有 `admin`（管理员）和 `user`（普通用户）。初始化创建管理员；邀请注册固定创建普通用户，请求中注入角色会被拒绝。普通用户只能访问自己添加的 SSH/Tailcat 主机；管理员的主机接口也遵守归属检查。实例维护者仍处于可信边界，能够接触部署数据和终端明文。

注册开启后沿用一次性邀请。关闭注册不注销已有用户；未使用且未过期的邀请码可在重新开启后使用，不需要时由管理员撤销。注册设置写入与审计在同一事务中，审计失败时回滚；管理页面提交版本号，过期页面不能覆盖更新后的设置。API 写操作继续要求管理员、同源和 CSRF。

已有本机记录不会被删除，但普通用户无法列出或访问。已有本机访问在下一次操作前、空闲复核时重新验证权限，失效后仅关闭工作台连接；不会停止 Herdr 或任务。工作台不新增角色提升或远程任务清理路径。

## 升级与边界

schema 2 将注册控制交给后台，旧 `HERDRX_REGISTRATION` 环境变量停用。首次升级会关闭注册，账号、登录、主机和加密凭据保留。schema 1 二进制不能直接打开新数据库；备份和恢复步骤见[迁移说明](update-and-recovery.md#访问管理迁移与旧版回退)。

本次浏览器验收使用隔离 Chromium 和移动尺寸模拟，未新增实体手机或跨网验收；Docker 运行验证为 amd64，其他发版差距仍按[发版清单](release-readiness-2026-09-06.md)跟踪。
