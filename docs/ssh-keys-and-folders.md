# SSH 密钥与主机文件夹

主机页顶部的「密钥」用于保存可复用的 SSH 认证密钥。密钥和文件夹归当前账号所有，其他账号无法列出、修改或引用。

## 添加与复用密钥

1. 打开「密钥 → 添加密钥」，填写便于识别的名称。
2. 粘贴或导入 OpenSSH/PEM **私钥**，也可将文件拖入输入区。导入文件最大 64 KB；加密私钥需填写对应的私钥口令。
3. 公钥可留空，由私钥自动提取。可选提供匹配的 SSH 用户证书。也可选择生成新的 Ed25519 密钥。
4. 保存后可以查看 SHA-256 指纹、复制公钥、修改名称或替换密钥，列表显示引用它的主机数量。
5. 添加或编辑 SSH 主机，选择「认证 → 选择已保存密钥（公钥认证）」，再选对应密钥。同一密钥可供多台主机使用。

公钥认证需要私钥进行签名，仅导入 `.pub` 公钥文件不能登录。网站生成公钥后，将它加入远程登录用户的 `~/.ssh/authorized_keys`；网站不会自动安装公钥。使用 SSH 用户证书时，远程 SSH 服务还需要信任签发证书的 CA。

私钥与私钥口令一起加密保存，页面不会回显已保存的私钥或口令，也不把它们放入浏览器本地存储。编辑时私钥留空保留原值，替换私钥需同时填写新私钥的口令。替换密钥后，引用它的主机需要重新建立网页 SSH 连接；远程 Herdr 和任务继续运行。仍被主机使用的密钥不能删除，先修改相关主机的认证方式或移除其连接配置。

## SSH 连接设置

「添加主机 → SSH」支持自定义主机名/IP、端口、SSH 用户和 Herdr 命名会话。可选填写 **跳板机 ProxyJump**（如 `user@jump-host:22`）：网站先连跳板，再经跳板转发到目标主机（单跳，语义接近 OpenSSH ProxyJump / `ssh -W %h:%p jump`）。跳板与目标共用同一认证（已保存密钥或密码）；不支持多跳、自定义 ProxyCommand 脚本、agent 转发，也不在 v1 固定跳板机主机密钥。认证方式包括已保存密钥、密码、单台主机私钥和为单台主机生成独立密钥。已保存密钥和密码是可选的两种登录方式，私钥口令用于解锁密钥，与 SSH 账号密码不同。

已有 SSH 主机通过主机条目上的「SSH 连接设置」按钮修改。密码或原私钥留空时保留已有认证；改用不同认证方式时需要重新选择密钥或填写凭据。保存连接配置后重新打开该主机。更换主机地址或端口会清除原地址的主机指纹信任，首次连接时需重新确认。

新标签页导入密钥后，可在主机表单点击「刷新密钥列表」直接选择，无需丢弃已填写的连接信息。删除主机只清理该主机专用的凭据，共享密钥会继续保留。

## 文件夹分组

主机页左侧支持新建、重命名、调整上级和删除文件夹，可创建子文件夹。「全部主机」显示所有条目，「未分组」显示没有文件夹的主机；选择文件夹显示直接放入其中的主机。

添加 SSH 或本机条目时可以选择所属文件夹。所有接入方式的已有主机，包括 Tailcat，均可通过条目上的「移动到文件夹」按钮调整归属。删除文件夹会把其中的主机和子文件夹移到上一级；删除顶层文件夹后，主机进入「未分组」。这些分组操作只修改网站组织信息，不断开终端，也不改变凭据。

## 存储与升级

本功能将数据库升级为 schema 3，新增 SSH 密钥元数据、文件夹和主机文件夹引用。既有主机、专用凭据、登录和配对身份保持不变，原主机初始显示在「未分组」。密钥材料继续使用现有 AES-GCM 凭据库，并绑定所属用户、凭据 ID 和类型。

升级前备份数据库与 `master.key`（或保留相同的外部主密钥）。schema 2 二进制不能直接打开 schema 3 数据库，不要手动降低版本号；恢复流程见[升级与恢复](update-and-recovery.md#访问管理迁移与旧版回退)。
