# Herdr 版本与功能兼容性

herdrx 分别检查远程主机上**安装的 Herdr CLI**和**正在运行的 Herdr 后台**。安装了新二进制不表示已有后台或任务已升级。工作台按具体功能判断兼容性，不会下载、升级、重启 Herdr，也不会为了探测能力创建 pane、输入文字或调整终端尺寸。

## 支持矩阵

| Herdr 版本 | 私有终端协议 | 当前适配与验证范围 |
|---|---|---|
| 0.8.2 | 20 | 已适配；固定 Linux amd64 二进制的隔离真实实例回归通过 |
| 0.9.0 | 22 | 已适配；固定 Linux amd64 二进制的隔离真实实例回归通过 |
| 0.9.1 | 22 | 已适配；固定 Linux amd64 二进制的隔离真实实例回归通过；其余平台 CI 见验证记录 |
| 其他版本、协议仍为 20 或 22 | 20 / 22 | 根据接口契约判断功能；标记“未覆盖版本”，不能据此称为完整验收 |
| 未适配的私有协议 | 其他值 | 禁用依赖该协议的终端观察、尺寸控制和保尺寸滚轮；已成功的 JSON 快照读取保留 |

平台清单、摘要固定方式和各平台实际运行状态见[固定版本门禁记录](terminal-compatibility-validation-2026-09-20.md)。版本矩阵不代表实体 Mac、手机、真实跨网或长时间运行已全部验收。

产品版本号不同不直接判定为不兼容。例如 CLI 0.9.0 与后台 0.9.1 都使用协议 22，可继续进行终端握手；CLI 0.8.2 与后台 0.9.1 分别使用协议 20、22，依赖 CLI 的尺寸控制受限，但工作台原生只读观察在后台协议已适配且尺寸可读时仍可使用。JSON 快照、输入和历史按各自证据判断。JSON 输入不会自动取得尺寸控制。

## 查看诊断

在“主机”页面打开对应主机的“Herdr 能力”详情。页面分别展示 CLI 和后台的版本、协议、各项功能状态与原因。诊断接口为 `GET /api/hosts/{hostID}/capabilities`，仅允许主机所属用户访问，响应不允许浏览器缓存。

| 字段 / 功能 | 证据来源与含义 |
|---|---|
| `cli.version` / `cli.protocol` / `cli.methods` | 固定只读命令 `herdr --version` 与 `herdr api schema --json`；只描述安装文件 |
| `daemon.version` / `daemon.protocol` | 当前命名会话的 `session.snapshot`；`ping` 身份一致时才保留其可选 capabilities 字段 |
| `snapshot` | 实际快照读取成功 |
| `observe` | 后台协议已适配，并成功只读取得目标终端几何时，使用工作台原生只读 observer，绕过 CLI 协议错配；尺寸无法读取时，另按 CLI 协议判断固定画布的观察退路 |
| `resize` | 后台协议已适配、CLI schema 有所需接口、CLI 与后台协议一致，同时具备可动态同步的观察画布；真正控制仍等待远端首个有效完整帧 |
| `input` | 已审查协议 20 / 22 的 `pane.send_text`、`pane.send_input` 契约；运行时明确拒绝方法会单独降级输入 |
| `history` | 已审查 `pane.read` 契约；存在 pane 时额外只读一行，验证当前服务实际支持 |
| `preserve_scroll` | 接入方式提供原生滚轮路径、协议已适配，存在 pane 时经只读 `pane.process_info` 和 `TIOCGWINSZ` 取得实际几何；使用时仍核对目标真实几何及 controller 冲突 |
| `generation` | 当前共享访问连接和已观察版本的代次；供工作台隔离旧缓存与旧尺寸控制，不是后台任务身份或存活承诺 |
| `coverage` | 版本是否列入固定版本回归矩阵，取值 `tested` / `untested`；不代替平台、网络或设备验收 |

功能状态为 `available`、`unavailable` 或 `unknown`。超时、暂时断网、目标 pane 消失、旧受控端拒绝新增只读诊断命令均不能证明后台缺少某项功能，诊断保持未知并允许重新检查。后台缺少可选 capabilities 字段时不补造声明。

空会话无法进行针对某个 pane 的几何读取，此时仅声明已适配的协议契约，真正打开终端仍校验具体目标。主机级诊断也不保证主机上每个 pane 都具有可读的 PTY；打开和操作时的校验仍生效。

本机和基础 SSH 使用固定只读命令；Tailcat 受控端仅新增两个完全匹配的命令白名单，不开放任意 Shell 执行。诊断有执行时限和输出大小限制。旧 Tailcat 受控端尚不接受这两个命令时，CLI 诊断可显示未知；已有 JSON 能力继续按实际响应判断。

## 缓存与失效

成功、完整的诊断最多缓存一分钟，同一连接的并发请求共享探测过程。能力接口每次先读取实际快照；WebSocket 的快照轮询也会更新后台身份。发现后台版本或协议变化、CLI 身份变化、访问连接被替换时，旧缓存和尺寸控制代次失效，终端需要重新建立观察与控制。相同版本的后台若在旧连接之下被外部原地替换且没有可用 boot ID，版本字段本身不能识别替换；传输断开、重连与终端关闭仍按各自路径失效。

明确的未知方法错误只禁用依赖该方法的功能。超时、网络错误、参数错误不缓存为“不支持”。未知状态不保留为完整缓存，下一次检查会重新探测；输入结果不确定时仍不自动重放输入。

受控端 `herdrx doctor` 同样分别打印 CLI 与经 socket `ping` 验证的后台身份。后台未回复完整身份时明确显示“尚未验证”，不使用 `status server` 的版本文本代替；CLI/后台协议不一致会提示终端功能受限，保留 JSON 接入，不自动修改远程环境。

## 终端尺寸的边界

默认保留远端任务的行列；浏览器字体、局部缩放、滚动和手机布局只影响当前显示。用户明确选择“使用此窗口尺寸”后，工作台才申请有有效期的尺寸控制并发送行列。本站不同窗口间的交接会先关闭旧访问 controller，不使用强制 takeover 抢占未知的原生客户端。

上游 CLI observe 的画布固定为启动时大小，且不读取 stdin。工作台因此使用协议 20 / 22 的窄范围原生 observer，通过 `ObserveTerminal` 和 observer `Resize` 让所有窗口的画布跟随真实任务行列；该通道拒绝输入和控制命令，不调整任务 PTY。controller 的有效画面与无控制时的周期只读几何检查负责同步观察画布。尺寸不可读时保留 CLI 固定画布观察，并拒绝在该观察流申请尺寸控制。

本轮没有启用字符格像素补发，也没有迁移到 ClientShell。真实实验表明普通 CLI control attach 会把像素 extent 清零；ClientShell 的语义输入还可能取得尺寸所有权。实验结论及继续禁用的原因见[像素与 ClientShell 记录](terminal-compatibility-validation-2026-09-20.md)，产品尺寸与交接验收见[尺寸验证记录](terminal-sizing-validation-2026-09-20.md)。
