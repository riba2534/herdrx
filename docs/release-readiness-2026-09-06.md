# herdrx 正式发版差距清单

评估日期：2026-09-06。范围：当前 `main/` 工作区，按较新的 [Tailcat v0.5 专项方案](design/tailcat-onboarding-v0.5.md) 及 [更新恢复要求](update-and-recovery.md) 评估。

**滚动结论（2026-09-07）：更新事务、服务入口与迁移、连接池、自建 DERP、端点迁移和签名发行链的本地实现已补齐，已形成独立本地候选和干净构建产物；完整发布仍等待首次远端 CI/分发与长期及跨网验收。** 其中既有已复现的缺陷，也有从代码确认的实现缺口，以及尚未执行的验收。工作包数量不代表相同工作量，也不能换算成完成百分比。

## R1：补齐更新与回滚事务

**原问题，已修复并回归：** 旧版升级到新版，再安装一次同一新版，`previous` 被覆盖成新版路径；随后 `rollback` 返回成功，但没有回到旧版。[实现位置](../internal/updater/updater.go#L81)

**原问题，已修复并回归：** 使用临时测试密钥签名的 `min_proto=999` 清单仍被接受。`MinProto` 仅定义，没有参与验证；数据格式兼容、过期和防降级规则也未形成完整检查。[清单验证](../internal/updater/updater.go#L18)

**原缺口，已补齐：** 旧更新过程只切换文件并提示手动重启；没有设计要求的预检、自检、更新锁、本地就绪检查、失败恢复。文件/目录同步和 `current`/`previous` 写入错误处理也需补齐。[CLI 更新](../internal/agentcli/update.go#L60)

- [x] 同版本更新幂等；不覆盖最后一个可用的兼容回退点。
- [x] 校验平台、协议和状态格式兼容性，定义清单时效与降级规则。
- [x] 更新及回滚互斥；处理磁盘不足、写入失败、中断和重复执行。
- [x] 候选程序自检后切换，通过服务管理器重启，30 秒内验证 IPC 版本及身份可加载。
- [x] 本地就绪失败回退并重启；外网故障不作为盲目回滚理由。

## R2：完成服务安装与迁移

**原静态发现，已修复并原生验证：** `setup` 将 `os.Executable()` 写入 systemd `ExecStart`。Linux 使用版本目录和稳定软链接安装时，它可能固定到旧版本真实路径；更新稳定链接后重启服务仍可能运行旧版。需在隔离测试机复现并修正。[入口](../internal/agentcli/cli.go#L211)、[unit 生成](../internal/agentcli/service.go#L109)

**已修复并回归：** `runSetup` 现在仅在确实没有旧配置时生成新身份。旧服务运行中、旧配置读取或迁移失败会明确返回错误，并保留原配置；新增从 CLI 调用入口触发的两种失败场景测试。[调用分支](../internal/agentcli/cli.go)、[回归测试](../internal/agentcli/onboarding_test.go)

- [x] 服务始终启动预期稳定入口；升级后 IPC 报告新版本。
- [x] 旧配置异常或旧服务尚未停止时，明确失败且不创建替代身份。
- [x] 验证旧名称服务停用、新服务启动、迁移失败恢复和 XDG 路径行为。
- [x] 在真实 Linux amd64/arm64 上验证首次 setup、重复 setup、SSH 登出、系统 reboot、stop/start/restart/uninstall。
- [x] 更新或停止 herdrx 时，Herdr 及 pane PID、任务保持不变。
- [x] 无 linger 时准确提示；connect 不再声称已保证登出保活，页面提供实际检查与启用命令。

已有 ServiceRunner 测试只能证明调用顺序，不能替代真实 systemd 生命周期验收。

## 推进顺序与退出标准

1. **修复阶段：** 先做 R1、R2、R3、R6 的测试修复，关闭回滚、身份迁移和不可执行命令问题。
2. **可靠性阶段：** 做 R4、R5，同时准备 R9 的干净构建、CI、签名候选产物与文档。
3. **候选验收阶段：** 在隔离真实机器执行 R7、R8，并启动 72 小时运行；自动门禁同步保留证据。
4. **发行阶段：** 同一候选 commit 的问题和证据全部关闭后，完成 R9 的公开分发和下载冒烟。

只有同时满足以下条件才标记“可正式发版”：

- 当前候选代码与产物可追溯，自动门禁通过；
- 安装、更新、回滚、备份恢复、撤销与重新接入有可重复结果；
- 声明支持的平台、跨网模式、浏览器和容量有验收记录；
- 72 小时运行完成，影响安全、身份、任务存活及恢复的阻塞问题清零；
- 发行文档与真实产物一致，新用户可以自行完成全流程。
